# SweetBloom POS

เว็บแอปจัดการร้านเค้กแบบครบขั้นตอน: รับออเดอร์ ส่งคิวเข้าครัว รับชำระเงิน จัดการเมนูและสต็อก พร้อม Docker และข้อมูลแบบเรียลไทม์

![หน้าเว็บ SweetBloom POS](docs/screenshots/shop.png)

## ความสามารถหลัก

- หน้าร้านสำหรับสั่งเค้ก นัดรับหรือจัดส่ง และติดตามสถานะ
- Kitchen Display สำหรับจัดการคิวผลิต
- แคชเชียร์รองรับเงินสด QR และบัตร พร้อมป้องกันการชำระซ้ำ
- Dashboard จัดการราคา สต็อก สถานะขาย ยอดขาย และส่งออก CSV
- Staff PIN, การซ่อนข้อมูลลูกค้า และ Server-Sent Events
- วิเคราะห์ลำดับออเดอร์ด้วย Jev API โดยไม่ส่งชื่อ เบอร์โทร หรือที่อยู่

## เริ่มใช้งานด้วย Docker

ต้องมี Docker Desktop, WSL 2 และพอร์ต `4173` ว่าง

```powershell
Copy-Item .env.example .env
docker compose up --build -d
```

เปิด `http://localhost:4173` ค่า Staff PIN เริ่มต้นคือ `2468` และต้องเปลี่ยนใน `.env` ก่อนใช้งานจริง

หยุดระบบ:

```powershell
docker compose down
```

ผู้ใช้ Windows สามารถใช้ `Start SweetBloom.bat` และ `Stop SweetBloom.bat` ได้โดยตรง

## วิธีใช้งาน

1. ลูกค้าสร้างออเดอร์ในหน้า **หน้าร้าน**
2. พนักงานเข้า **ครัว** ด้วย Staff PIN แล้วยืนยัน เริ่มทำ และทำเสร็จ
3. **แคชเชียร์** ตรวจยอดและบันทึกการชำระ
4. เมื่อชำระแล้ว ครัวจึงส่งมอบและปิดออเดอร์
5. **จัดการร้าน** ใช้ปรับเมนู ราคา สต็อก ดูยอด และดาวน์โหลด CSV

## การตั้งค่า

| ตัวแปร | หน้าที่ |
|---|---|
| `STAFF_PIN` | รหัสเข้าหน้าพนักงาน |
| `PROMPTPAY_ID` | หมายเลข PromptPay ของร้าน |
| `JEV_AI_API_KEY` | เปิดการวิเคราะห์ออเดอร์ด้วย Jev |
| `PORT` | พอร์ตของแอป ค่าเริ่มต้น `4173` |

ข้อมูลร้านเก็บใน Docker volume `sweetbloom-data` ส่วน `.env`, API key, log และข้อมูลออเดอร์จะไม่ถูก commit

## ตรวจสอบระบบ

```powershell
npm test
npm run check
docker compose config --quiet
```

ระบบนี้ยังไม่ได้เชื่อม Payment Gateway หรือระบบใบกำกับภาษีอิเล็กทรอนิกส์ ก่อนเปิดใช้งานผ่านอินเทอร์เน็ตควรวางหลัง HTTPS reverse proxy และสำรอง Docker volume เป็นประจำ
